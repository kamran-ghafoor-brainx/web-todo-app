## Summary

Stack: React (React 19, Redux Toolkit, React Router, React Hook Form + zod, Tailwind). Single repo.
Scope: all changes (everything was already staged with `git add -A`).

Adds a reusable `TodoForm` (title, description with a character counter, optional due date)
built on React Hook Form with `todoFormSchema`, plus `AddTodoForm`, which wraps it in a
labelled section and dispatches `createTodo(...).unwrap()`. Server and network errors are
routed through the shared `showSubmitError` helper. With `resetOnSuccess` set, the form
clears and puts focus back on the title after a successful save. `TodosPage` now renders
the add form above the filters and connects the list's "Add your first todo" button to the
title input through a ref. New `messages.todoForm` strings, barrel exports and tests
(TodoForm, AddTodoForm, TodosPage) are included.

Checked against the surrounding code: `todoSchemas` (trim → min/max, `toTodoRequest` mapping
empty strings to `null`), `formErrors.showSubmitError` / `fieldError`, the `createTodo` thunk
(its rejected value is a user-facing string, so `.unwrap()` throws a string that
`showSubmitError` shows as is), the slice's `settle`/`commit` (a new todo is put first in the
list without duplicates), `TextField`/`TextArea` prop forwarding, `TodoList`'s `onAddFirst`,
and the existing `SignupForm` pattern (this form follows it). RHF only reports
`isSubmitSuccessful` when there are no errors, so a failed save leaves `errors.root` set and
does not trigger the reset effect. The "keeps what was typed" test with
`resetOnSuccess: true` covers this. The submit button is disabled while saving, so a double
click can't send two requests. `tsc -b` and ESLint (src, tests) run clean, and Vitest (todos
and pages suites) passes 108/108.
