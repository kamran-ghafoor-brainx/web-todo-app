## Summary

Stack: React (React 19, Redux Toolkit, React Router, Tailwind). Single repo.

`TodoList` now covers every list state: a skeleton (announced via `role="status"`) on the
first load, an error alert with a "Try again" button that re-dispatches `fetchTodos`, a
first-time empty state with an optional "Add your first todo" action (`onAddFirst`), and a
"no matches" empty state for the active filter that links back to All. When todos are
already loaded, a reload keeps the list on screen, and a failed reload shows the error
above the list. List strings moved from `messages.todosPage` to a new `messages.todoList`
group, and the TodosPage tests were updated to match. A new `TodoList.test.tsx` covers
each state.

Checked against the surrounding code: `selectTodoCounts`, `useFilteredTodos`, `useTodoFilter`,
`searchForFilter`, `EmptyState`, `Alert` (its `action` prop), `LinkButton`, the `fetchTodos`
condition guard (stops duplicate fetches when Retry is clicked during a load), and the slice's
status/error transitions. No remaining references to the removed `todosPage.loading` /
`todosPage.listLabel` keys. Vitest (todos and pages suites: 94/94 passing), `tsc -b`, and
ESLint on the changed files all run clean.

Note, not a finding: `TodosPage` does not pass `onAddFirst` yet, so the real page shows the
first-time empty state with no button. This is intentional and tested ("leaves out the call
to action when no add action is given"), and it is presumably wired up when the add-todo
form lands.
